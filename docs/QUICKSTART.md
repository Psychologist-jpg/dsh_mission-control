# 快速入门 · Mission Control

> 5 分钟从零跑通一次蜂巢任务：开启蜂巢模式 → 声明任务 → 拆解配平 → 开子会话 → 看进度 → 收尾汇总。

本页只讲「怎么用」，功能细节与配置见 [README](../README.md)。

---

## 0. 前置检查（30 秒）

装好并重载 DSH 后，新建一个会话，确认三件事：

1. 会话**头部右侧**出现蜂巢模式开关（`普通 / 蜂巢 / 已暂停`）与人数选择器；
2. 页面**右下角**出现「蜂巢任务」悬浮窗（没有任务时不会显示内容，开启后出现）；
3. 工具列表里有 `mission_start`、`mission_scale`、`mission_report`、`mission_status`、`mission_stop`（另有 `mission_set_model`、`mission_image`）。

缺任何一项 → 回到 README 的「安装与启用」核对 profile 的 `dependencies` 与 `dsh.profile.bundles`。

---

## 1. 开启蜂巢模式（图形界面）

在会话头部点击开关：

| 状态 | 含义 |
| --- | --- |
| `普通` | 未开启，不会创建任务，工具调用会报「没有进行中的蜂巢任务」 |
| `蜂巢` | 已开启，主会话消息会下发给所有子会话 |
| `已暂停` | 子会话仍在跑，但主会话消息**不再**下发（想安静推进时用） |

旁边的数字选择器（2–10）设定**并发子会话上限**。

> 也可以用命令开启：让 Lead 调用 `mission_start`（见下一步），效果等价。

---

## 2. 提示词怎么说（最关键的一步）

开启后直接说清楚**目标、产出、验收标准**就够了。插件会自动注入分派契约，让 Lead 先拆解、再按需开子会话。

✅ 好的写法：

```text
帮我为一个开源插件写一套发布材料：
1) README.md（中文，含安装、配置、示例）
2) 一份 3 页的产品介绍（含一张封面图）
3) 一份 CHANGELOG（含 v1.0.0）

要求：每个文件独立成篇；封面图用 mission_image 生成；
全部完成后把文件放在 docs/ 下，并在最后给我汇总。
```

这个例子里，自然可以拆成 3 个独立子任务 → 目标人数 = min(3, 上限)。

❌ 不太好的写法：

```text
帮我写点东西
```

目标模糊时，Lead 难以拆解，配平统计里的「待办数」也会是 0，不会开启子会话。

## 3. 典型交互流程（Lead 会自动完成的动作）

你只负责说需求，下面这些动作由 Lead 按提示词契约自动执行，你可以顺便核对：

```text
① mission_start(task="…", workers=3)          # 记录目标 + 锁定人数上限
② team_task_create × N                        # 把目标拆成 N 个独立子任务上任务板
③ mission_scale(workers=[{name, task}, …])    # 一次性开出所需子会话（只补差额）
④ （子会话）认领任务 → 干活 → mission_report   # 面板上出现「当前任务 / 已完成」人话进度
⑤ （Lead）验收 → 汇总                          # 全部 completed 后给你最终结果
```

### `mission_scale` 的参数长什么样

```json
{
  "workers": [
    {
      "name": "readme-writer",
      "task": "写 README.md：中文，包含简介、安装、配置项表格、HTTP 接口、示例。产出路径 docs/README.md，完成后报告。"
    },
    {
      "name": "deck-maker",
      "task": "做 3 页产品介绍（Markdown 页面，含一张封面图），封面图调用 mission_image 生成。产出路径 docs/deck/，完成后报告。"
    }
  ]
}
```

返回值会告诉你实际发生了什么：

| 字段 | 含义 |
| --- | --- |
| `spawned` | 真正新开的子会话名 |
| `skipped` | 已存在、被跳过的名字 |
| `refused` | 超出上限或参数非法的名字 |
| `workers` / `cap` | 开完后的人数 / 上限 |
| `modelSwitches` / `modelErrors` | 生图模型切换结果（开启 `imageModelSwitch` 时才有） |

**常见情况**：

- 已经开过两个，想再补一个 → 直接把 **三个都传进去**，已存在的会被 `skipped`，只补差额；
- 名字和花名册里的历史条目重名 → 自动改成 `name-2`、`name-3`，以 `spawned` 返回的为准；
- 想调整已开工蜂的名字或任务 → 任务板上的归属不会自动迁移，需要在任务板上重新认领。

## 4. 看进度：悬浮窗还是工具

### 悬浮窗（零 token）

每个主会话一个独立窗口，可拖动、可折叠，位置会记住：

```text
● 任务标题                     3/5 工蜂 · 待办 2 · 建议再开 1
  ├ ● readme-writer  [工作中]  ▓▓▓▓░░░░  42%
  │   当前任务：写 README 安装章节
  │   已完成任务：调研目录结构；起草简介
  │   产出文件：README.md
  │   模型：deepseek-v4-flash
  └ ● deck-maker     [已完成]  ▓▓▓░░░░░  31%
      当前任务：—
      已完成任务：3 页产品介绍
```

- 进度条颜色：绿 → 黄（65%）→ 红（85%），红色表示该工蜂快到交接线了；
- 标题栏 `3/5` = 现有工蜂 / 上限，`建议再开 N` = 配平缺口；
- 右上角「结束任务」按钮 = 完整收尾（见第 6 步）。

### `mission_status`（只读，零 token）

```text
Mission: 为插件写发布材料
Cap: 3
- readme-writer [running] 55000/131072 tokens (42%)
  当前任务: 写 README 安装章节
  已完成任务: 调研目录结构；起草简介
  最近进展: 已写完安装章节，正在补配置表
```

## 5. 中途干预的三种方式

| 想做的事 | 怎么做 |
| --- | --- |
| 让所有人改方向 | **直接在会话里说话**，会被包装成 `[驾驶舱广播] …` 立即发给所有子会话 |
| 暂时不想打扰子会话 | 开关切到「已暂停」，子会话照常干活，只是收不到你的新消息 |
| 某个工蜂卡住 / 上下文快满 | 什么都不用做，哨兵到 85% 会自动中断它并开一个 `<name>-r1` 继任者接着干 |

## 6. 收尾

点悬浮窗「结束任务」（或在会话里说「结束任务」），插件会依次：

1. 中断所有存活子会话；
2. 归档它们（侧边栏不再堆积），清理孤儿归档；
3. 删除临时文件（`*.tmp` / `*.log` / `*.bak` 等，结果文件不动）；
4. 收集本次产出的**结果文件**（从工蜂的写文件调用 + 任务期间修改过的文件里找）；
5. 给 Lead 投递一条「【蜂巢任务已结束】」汇总指令 → Lead 输出最终摘要并 `present` 交付物。

之后悬浮窗会弹出一张「已结束」小卡片（15 秒后自动消失）。

## 7. 常见问题

**Q：开不了子会话，报「上限是 N 个并发工蜂，已满」？**
说明当前存活子会话已达上限。先在悬浮窗「子会话」弹窗里归档不再需要的，或把头部的人数调大。

**Q：`mission_scale` 一直 `refused`？**
多半是缺少 `name` 或 `task`（两者都必填），或者超出上限。看返回里 `refused` 的具体名单。

**Q：子会话列表里那些灰掉的「已删除」条目是什么？**
历史残留（平台无法移除成员）。它们不参与广播、计数和命名，可直接忽略。

**Q：想要配图，但切到图像模型后对话就崩了？**
图像模型不能承担对话请求。正确做法是让工蜂调用 `mission_image`（它直接出图落盘），而不是切换对话模型；`imageModelSwitch` 保持默认 `false`。

**Q：悬浮窗没出现？**
先确认已开启蜂巢模式（任务存在才会渲染）。若仍没有，刷新页面或重启客户端让客户端插件重新加载。

## 8. 一页速查

```text
开启蜂巢 ──► 说清楚目标/产出/验收 ──► Lead 自动拆解+开人
     ▲                                      │
     │                                      ▼
 暂停/广播 ◄──── 悬浮窗看进度 ◄──── 子会话干活 + mission_report
     │                                      │
     └────────► 点「结束任务」────────► 汇总 + present 交付物
```

| 工具 | 一句话 |
| --- | --- |
| `mission_start` | 声明任务 + 锁人数 |
| `mission_scale` | 只补差额地开人 |
| `mission_set_model` | 给某个工蜂换模型 / 换回来 |
| `mission_image` | 生成图片并落盘 |
| `mission_report` | 工蜂自报「在做什么 / 做完了什么」 |
| `mission_status` | 只读查看实时状态 |
| `mission_stop` | 结束任务、解除上限 |
